About

A LiteLLM proxy server that exposes AWS Bedrock Mantle models and other providers via a single OpenAI-compatible API. Useful for claw-code, opencode, or other apps expecting an OpenAI response.

GitHub: https://github.com/jeshii/claw-bedrock

Client Integrations

Point your OpenAI-compatible client at the proxy:

curl detecting.../chat/completions \
  -H "Authorization: Bearer sk-claw-xxxx" \
  -H "Content-Type: application/json" \
  -d '{"model": "my-model", "messages": [{"role": "user", "content": "Hello"}]}'

Or with the OpenAI Python client:

from openai import OpenAI
client = OpenAI(
    base_url="detecting...",
    api_key="sk-claw-xxxx",
)

opencode.ai

Set baseURL in ~/.config/opencode/opencode.json: 

{
  "provider": {
    "claw-bedrock": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Claw Bedrock",
      "options": {
        "baseURL": "detecting...",
        "apiKey": "sk-claw-xxxx"
      }
    }
  }
}

To keep the key out of the config file, export it as an env variable and reference it with {env:MY_API_KEY}.

claw-code

Set these environment variables:

OPENAI_API_KEY="dummy"
OPENAI_BASE_URL="detecting..."

Replace "dummy" with your actual key above.

Model names are usually prefixed with claw-bedrock/ unless the prefix toggle on the Models page is off.

Adding Models

Use the Models page to add from Bedrock, OpenRouter, Ollama, or manually. Changes auto-restart LiteLLM to pick up new config.

Required/Optional Environment Variables:

  • OpenRouter: OPENROUTER_API_KEY (optional but recommended for rate limits)
  • Ollama: OLLAMA_API_BASE (default: http://localhost:11434)
  • Bedrock: AWS_PROFILE, AWS_REGION (region is also settable in the UI). Optional static keys: AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY. Leave BEDROCK_MANTLE_API_BASE unset unless you use a private/VPC/GovCloud endpoint.

Bedrock credentials can also be entered in the UI (Providers → Bedrock Authentication); environment variables take precedence. OpenRouter prices are auto-filled when you pick a model from its catalog.

Managing Models

  • Click a model to expand details and manage it
  • Rename makes the name editable; click Confirm to save
  • Click Delete for confirmation flow (line turns red, wait 1s, then confirm)
  • Edit In/Out $/1M costs for cost-based routing; a model without a cost is skipped
  • Set Reasoning level (low/medium/high) or a thinking budget where supported
  • Assign a Group to enable failover between models sharing a name
  • Add/remove Tags via the tag input; drag tag chips between models to copy
  • Models auto-restart LiteLLM to pick up changes

The Add claw-bedrock/ prefix to model names toggle on the Models page controls whether served model names are prefixed. Keep it consistent with what your client expects.

Providers

Providers are reusable backend definitions (Bedrock, OpenAI-compatible, or custom). Create and edit them on the Providers page; their color and notes are for your reference.

  • Bedrock Authentication: region, AWS profile, and an optional static IAM key pair are configured once for all Bedrock models. Values show a source badge when an environment variable is overriding what you typed.
  • Static keys are encrypted at rest and never shown again after saving; a half-configured key pair falls back to the profile.
  • OpenAI-compatible providers need an API base URL and optional API key; models added from them propagate endpoint and credentials automatically.
  • Renaming a provider updates all model references.

Groups

Models sharing a group name are served under a single LiteLLM model name, giving automatic failover between members. Status reflects what is written to the generated config, not live provider reachability.

  • Router Settings: routing strategy (shuffle, latency, usage, or cost-based), allowed fails before deactivation, and retries within the group.
  • Rename a group (clients calling the old name stop working) or Unassign to split members back to individual names.
  • Add member: pick an ungrouped model from the dropdown.
  • Member status chips: Ready, Check config, Not in config. Group headers show active vs total member counts.
  • Under cost-based routing, members without a cost show a no cost warning and are skipped.

Playground

Session-scoped chat with multi-turn in-memory context; responses stream in real time. Pick a model, add an optional system prompt, and send.

  • Hands-free audio mode (Chrome/Safari): toggle the mic, speak, pause, and the transcript is sent after a short grace window; the reply is read aloud as it streams.
  • Press Esc, start a new chat, or leave the page to disarm the mic.
  • Use the refresh button to reload the model list.

Tags

Tags let you label and filter models on the Models page. Create tags on the Tags page, then add them to models via the model detail panel.

  • Create a tag: Go to the Tags page, click Create Tag, type a name, pick a color, and press Add or hit Enter.
  • Add a tag to a model: Click a model to expand it, then type in the Add tag input. Matching tags appear as you type — click one or press Enter to add it.
  • Drag and drop: Tag chips on model rows can be dragged onto other models to copy the tag.
  • Remove a tag: Click the × on a tag chip to remove it from that model.
  • Filter by tag: Click a tag in the filter bar above the model list to show only models with that tag.
  • Rename a tag: On the Tags page, click a tag name to make it editable.
  • Change tag color: Click the color swatch next to a tag to pick a new color.
  • Delete a tag: Click Delete on the Tags page to remove a tag entirely.

Login

The management UI is password-protected. Set the MANAGEMENT_UI_PASSWORD environment variable to enable it.

  • Navigate to the management UI — you will be prompted to enter the password.
  • After logging in, a session cookie is set that lasts 24 hours.
  • Click Logout in the sidebar to end the session immediately.
  • If MANAGEMENT_UI_PASSWORD is not set, no login is required.

Security

The Security page manages the LiteLLM master API key. When a key is set, all proxy requests must include Authorization: Bearer <key>.

  • Generate New Key creates a key; copy it immediately — it is shown once.
  • Revoke Key disables authentication on the next reload.
  • Provider API keys and Bedrock static keys are encrypted at rest using ENCRYPTION_KEY or ENCRYPTION_PASSWORD. Using the built-in development key triggers a warning banner.

Backup

Export downloads a complete snapshot (models, tags, providers, settings) as JSON. Import restores from a file: Replace overwrites all current data, Merge adds records without removing existing ones. A preview is shown before applying.

Backups contain plaintext API keys; keep them safe. Restoring under a different encryption key may require regenerating the master key.

Logs

Three log streams are available: LiteLLM, TokenRefresher, and container stdout/stderr. Use Refresh or enable auto-refresh at 2s/5s/10s. LiteLLM output is written to litellm.log in the config directory, not to container stdout.
